# Spacing Auto-Fix (Feature 4, Task 2)

**Gathered:** 2026-10-23
**Spec:** `.specs/features/preview-area-auto-fix/tasks/spacing-auto-fix/spec.md`
**Status:** Specified — awaiting implementation

## Feature Boundary

Punctuation-adjacent spacing in the preview (inline and modal), for Feature 4 Task 2 only (roadmap Task 2.1–2.3): a pure spacing pass in the preview document utils — no space before `.` `,` `!` `?` `;` `:` `…` `)` (the roadmap's `.,!;:` list plus `?`, a roadmap omission, plus `…` aligned with the case pass's sentence enders, plus `)` per the roadmap's own "before `)`" rule), no space after `(`, exactly one space between content atoms (collapse every whitespace run of two or more inside own text to one), literal trim of ALL whitespace adjacent to line breaks (line-break tokens themselves never added or removed), trim of leading/trailing document whitespace, and — the user's deliberate extension beyond the roadmap's removal-only wording — **insertion** of one missing space after a punctuation-ending token at token-boundary seams (chip↔own text, own text↔chip, chip↔chip; never inside token interiors; never before a line break or at the document end). The trailing-whitespace EDGE of a non-frozen chip is seam material (stripped when a rule demands it; chip interiors are never rewritten); frozen chips' text — edges included — is never touched, though the spacing around them is corrected. The auto-fix pass becomes the composition **case → spacing → case** (the first case stage sees the exact pre-spacing structure, preserving every pinned Task 1 classification; the final case stage re-cases only chips the insertions un-glued, so one application reaches the settled document) wired centrally in the exported `snippetsReducer` wrapper on EVERY transition except `SYNC_DOCUMENT`, after the source-text rewrite and eager normalization — idempotent, reference-stable, whole-document recompute; the copy path (`CopyMergedTextButton.hook.tsx`) serializes the composed-pass output over a transformed copy so the clipboard is always fully corrected without mutating the document; reconciliation's no-op guard canonicalizes through the composed pass (spacing-only re-emissions are reference-identical no-ops) while `SYNC_DOCUMENT`'s edited-detection and the focused-surface comparison stay exact; ADR 0005 amended in place (draft in the spec; the Developer writes it); the roadmap Task 2.1 line's `?` addition annotated at completion (orchestrator); and the test suites (unit spacing rule tables + create/sort/copy integration, existing oracle suites at behavior level with the listed deliberate updates). One roadmap amendment recorded with user decision date 2026-10-23: the before-set's `?` addition (the roadmap line's `.,!;:` includes `!` but omits `?` — treated as a typo and amended; annotated at completion). Explicit NOTs: no insertion inside token interiors (decimals, URLs, "e.g." live there), no chip-interior rewrites of any kind, no line-break token insertion/removal, no per-language spacing rule table (plain module constants), no new i18n strings, no GLOSSARY changes, no routes, no DOM/testid changes in production code, no undo UI (Feature 4 Task 3 stays a deferred placeholder), no modification of the source TextInputs, no mid-typing correction (the `SYNC_DOCUMENT` skip stays), no backend files.

## Implementation Decisions

### Grilling record and scope

- Two rounds, 17 answers, all dated 2026-10-23: Round 1 (Q1–Q13) settled scope, structural mutations, frozen semantics, pass order, the insertion policy, punctuation sets, line-break trim, document edges, the comparison policy, the document limit, language keying, records, and tests; Round 2 (Q1–Q4) settled the insertion seams, trigger set, space placement/minting, and the composed-pass fixpoint.
- **User decision (2026-10-23, R1-Q1)**: "Task 2 only (Recommended)" — Tasks 2.1–2.3; the undo task and per-language divergence stay deferred placeholders.

### The pass and its rules (Task 2.1)

- **User decision (2026-10-23, R1-Q6 + R2-Q2)**: "Accept proposed set (Recommended)" / "Same 8-char set (Recommended)" — no space before `.` `,` `!` `?` `;` `:` `…` `)`; no space after `(`; `(` is the lone opposite (never a removal-before target, never an insertion trigger). The before-set adds `?` to the roadmap's `.,!;:` (a roadmap omission — the list includes `!` but omits `?`; amended and annotated at completion), `…` (aligned with the case pass's sentence enders), and `)` (the roadmap's own "before `)`"). Brackets `[ ] { }` and quote pairs are deferred. The rules fire wherever the space lives — inside own-text tokens (interior and edges), in separator tokens at chip↔chip seams, and in the trailing-whitespace edges of non-frozen chips.
- **User decision (2026-10-23, R1-Q2)**: "Edges are seams (Recommended)" — the pass mutates document STRUCTURE: it rewrites own-text token text (`"foo  bar"` → `"foo bar"`, `" ."` → `"."`), removes separator tokens, drops own-text tokens that become empty, and treats the trailing-whitespace EDGE of a non-frozen chip as seam material (stripped when a rule demands zero spaces or when other material provides the one space). Chip INTERIORS are never rewritten; frozen chips are fully untouched. Tombstones are snippet-id-only (verified in the code), so removed own-text/separator tokens need none; no token-id minting except the insertion case below.
- **User decision (2026-10-23, R1-Q7)**: "Literal trim (Recommended)" — remove ALL whitespace adjacent to line-break tokens on both sides (own-text edges and non-frozen chip edges); `A \n B` → `A\nB`; line-break tokens themselves are never added or removed; chips with internal line breaks keep their internal padding (interior).
- **User decision (2026-10-23, R1-Q8)**: "Trim both edges (Recommended)" — trim leading whitespace at the document start and trailing whitespace at the document end; the pinned `'\nA bee '` oracle seam becomes `'\nA bee'` (a listed deliberate update).
- **User decision (2026-10-23, R1-Q5)**: "Insert after punctuation" — the user's divergence from the recommended never-insert policy: when a token ENDS with one of the eight trigger characters and the next atom abuts with ZERO whitespace, the pass inserts exactly one space.
- **User decision (2026-10-23, R2-Q1)**: "All token-boundary seams (Recommended)" — insertion fires at chip→own text, own text→chip, AND glued chip↔chip seams; the principle recorded verbatim: "the pass fixes seams between materials; glue inside one material is the user's". Token INTERIORS are never touched by insertion (decimals, URLs, `"3.14"`, `"e.g."` live there; the removal/collapse rules still fire inside own text — they only delete misplaced whitespace). Non-punctuation glue (chip `"Alpha"` + own `"mytext"` — the pinned `Alphamytext` seam) stays glued. A user who genuinely wants `"Hello,world"` can keep it by typing it as a single own-text run (the escape hatch). Insertion never fires before a line break or at the document end.
- **User decision (2026-10-23, R2-Q2)**: the trigger set is the same 8 characters as the no-space-before rule (`.` `,` `!` `?` `;` `:` `…` `)`); `(` excluded. Conflict priority: when the follower STARTS with a no-space-before character, the removal rule wins — no insertion (`chip "Hello,"` + `own ",more"` stays zero-space). Abbreviation-blindness accepted (`"Dr."` + `"Smith"` → `"Dr. Smith"`), mirroring the case pass's accepted `"Dr."` behavior.
- **User decision (2026-10-23, R2-Q3)**: "Split policy (Recommended)" — the inserted space lives in the own-text side whenever one exists (chip→own text: prepend to the following own text; own text→chip: append to the preceding own text; chips' leading edges are never touched, so a frozen follower is no obstacle). At chip↔chip seams: append to the preceding chip's trailing edge when it is non-frozen; when the preceding chip is frozen, mint a separator token with the existing `${rightChipTokenId}:separator` id pattern (deterministic, idempotent, cannot double-mint — the id is free again because the glue only exists after the original separator was deleted).
- **User decision (2026-10-23, R2-Q4, limit half)**: insertions that would push the serialized document over `PREVIEW_DOCUMENT_MAX_LENGTH` are skipped, applied in document order (deterministic); the pass never clamps user content to make room for a correction; everything else the pass does only rewrites or removes (never grows the document otherwise); a skipped seam is re-evaluated at the next trigger (a later shrink may afford it). The length-gate memo in `PreviewArea.hook` keeps measuring the model — unchanged.

### Wiring, composition, frozen semantics (Task 2.2)

- **User decision (2026-10-23, R1-Q4, extended by R2-Q4)**: "Case then spacing (Recommended)" → refined to "Case→spacing→case (Recommended)" — the composed auto-fix pass is case → spacing → case in BOTH the reducer wrapper and the copy memo. The first case stage runs on the exact pre-spacing structure (preserving every pinned Task 1 classification); the final case stage re-cases only chips the spacing stage's insertions un-glued (verified: it never reverses earlier corrections), so one application reaches the settled document — the fixpoint — keeping the "clipboard is always fully corrected" contract true. The two-stage alternative was rejected: an insertion that un-glues a chip follower would leave the document one re-case short of settled for a full trigger cycle and the copy path could ship a not-fully-corrected payload.
- **User decision (2026-10-23, carried from Task 1's Q2)**: central wiring — the composed pass runs in the exported `snippetsReducer` wrapper on EVERY transition except `SYNC_DOCUMENT`, after the transition's source-text rewrite and the eager `normalizeTextTokens`, no-op transitions included; whole-document recompute; idempotent; reference-stable (nothing changes → the same state object returns). `SYNC_DOCUMENT` keeps the mid-typing skip entirely (ADR 0004's focused-surface contract).
- **User decision (2026-10-23, R1-Q3)**: "Confirm (Recommended)" — frozen = the chip's own text only (including its edge whitespace — no edge strip on an edited chip); all own-text/separator spacing AROUND a frozen chip is still corrected (frozen `"Stop"` + own `" !"` → `"Stop!"`; a separator before a punctuation-initial frozen chip is removed; a frozen chip's redundant adjacent separator is removed with the frozen edge providing the one space). Accepted consequence: a frozen chip keeps a trailing edge space at the document end and before line breaks (frozen wins over trims).
- **User decision (2026-10-23, R1-Q9)**: the mixed comparison policy carries over and extends — (1) reconciliation's no-op guard canonicalizes both sides through the COMPOSED pass (case+spacing), so a spacing-only re-emission (the source re-sends `"wordA "` while the stored chip was edge-stripped) is "no change" and returns the reference-identical state; (2) `SYNC_DOCUMENT`'s edited-detection (`previous.text !== token.text`) stays EXACT (a deliberate spacing retyping freezes the chip); (3) the focused-surface comparison (`tokensEqualIgnoringEdited`) stays EXACT (a spacing correction is never mistaken for the surface's own typing). Visibility consequences accepted: corrections visibly flip at triggers; a sort while edit-ON+focused re-renders the surface (caret reset — ADR 0004's non-text-change path); stale visible spacing after typing until the next trigger; copy always fully corrected.

### Copy path

- **User decision (2026-10-23, carried from Task 1's policy)**: the clipboard is ALWAYS the settled (composed-pass) serialization — `serialize(applyAutoFix(previewDocument, caseFixLanguage))` — over a transformed copy of the tokens; the context document is never mutated by copying; the one component serves the toolbar and the modal rail (ADR 0003), so both copy buttons get the fix for free; the memo re-derives on document or language change.

### Language

- **User decision (2026-10-23, R1-Q11)**: "Module constants (Recommended)" — spacing rules are language-independent plain module constants (the documented extension point); no per-language table until a real divergent rule exists (e.g. French-style spacing before punctuation). The wrapper still re-runs the composed pass on `SET_CASE_FIX_LANGUAGE` dispatches (spacing stage = idempotent no-op; case stage keyed by the state's `caseFixLanguage` field).

### Tests and records

- **User decision (2026-10-23, R1-Q13)**: "Confirm (Recommended)" — existing oracle suites pass at the behavior level with only listed, deliberate assertion updates: (a) the `'\nA bee '` trailing-gap seam → `'\nA bee'` (document-edge trim); (b) the reducer sweeps' character-multiset guards and non-inert pins become spacing-tolerant (whitespace-insensitive multiset or canonical-form comparison); (c) move/landing expectations where the move logic deliberately leaves double spaces now collapse to one; (d) the glued seams (`Alphamytext`, `mytext XBeta`, `Xbeta`) stay UNCHANGED and get pinned as deliberate; (e) clean single-space seeded documents unchanged. New suites: unit spacing rule tables (each rule × each seam kind, idempotence + reference-stability rows, insertion mechanics incl. minting + limit-skip) + integration (creation, sort, copy outputs inline + modal, no document mutation, stale-visible-spacing, frozen-chip boundary corrections, glue preservation).
- **User decision (2026-10-23, R1-Q12)**: "Extend ADR 0005 (Recommended)" — amend `docs/adr/0005-preview-auto-fix-pass.md` in place, dated 2026-10-23, per the established inline amendment pattern (mechanism sentences + consequences bullets, as in ADR 0004's "(ADR 0001 amendment)" style); the amendment draft lives in the spec; the Developer writes the file. NO new i18n strings, no GLOSSARY changes; the roadmap Task 2.1–2.3 checkoff and the Task 2.1 `?`-addition annotation happen at completion (orchestrator).

### Agent's Discretion

- Export names and internal decomposition in `previewDocument.ts` (e.g. `applySpacingFix`, `applyAutoFix`, extending `tokensEqualCanonicalCase` vs. a sibling canonical-comparison helper) — semantics pinned, names free; the pinned observable for the guard: spacing-only re-emissions return the reference-identical state.
- The collapsed-space identity: whitespace runs are identified by the same `/\s/` predicate the case pass uses, and each maximal run inside own text collapses to one U+0020 space (tabs/non-breaking spaces included).
- Which token survives a collapse: the serialized observable is pinned ("exactly one space"); a coherent deterministic preference matching the placement policy — own-text-side material first, a separator token at chip↔chip seams, a non-frozen chip's trailing edge only when it is the seam's only material — is recommended, not mandatory.
- The rule-constant shape (one shared constant serving the before-set and the insertion-trigger set, or mirrored constants) — content pinned (`.` `,` `!` `?` `;` `:` `…` `)` / `(`), shape free.
- The composed pass's internal structure (three literal `applyCaseFix`/`applySpacingFix` calls vs. a fused implementation) — the pinned observable is stage order: case on the pre-spacing structure, spacing, then case again.
- Test placement within the listed suites; no new testids; no UI/DOM changes.
