# The preview is a token document and the focused editable surface owns its DOM

SnippetsContext state becomes a single ordered `PreviewToken[]` — snippet tokens, own-text tokens, line-break tokens — where array position IS the merge order (the `order` integer and MOVE_SNIPPET's dense renumbering are retired; ADR 0001's diff-by-id now reconciles snippet tokens inside the document). Every character of the merged output belongs to exactly one token: the implicit join-space becomes a `" "` own-text token, so serialization is pure concatenation and an unedited session copies byte-identically to the old `join(' ')`. Snippet tokens reference their source snippet: unedited tokens track source updates (a resize rewrites their text; source deletion removes them together with one adjacent separator token); tokens the user has typed inside are text-frozen but their existence still follows the source; ids whose tokens the user deleted from the document are tombstoned so later source emissions cannot resurrect them. Editing is gated by a session-level edit toggle (default off). While edit mode is on and a surface is focused, React must not reconcile that surface's token children in response to its own parsed edits: the focused DOM is the source of truth for a pure DOM→tokens parser whose result dispatches as one whole-document sync; the blurred twin re-renders live from the model; non-text model changes (reorders, source-driven reconciliation) re-render the focused surface too, accepting a possible caret reset after a drag. With edit mode off, the surface is exactly the previous read-only sortable flow.

## Considered Options

- **Keeping the snippets array plus a parallel overlay of own text/line breaks** — rejected: two sources of truth for one sequence; the overlay needs its own indexing, its own reorder mapping, and its own deletion rules, and every consumer (copy, twin surfaces, drag math) must merge them back on every read.
- **Rendering the editable flow via `dangerouslySetInnerHTML` with update-skipping** — rejected: dnd-kit cannot attach refs, attributes, or listeners to innerHTML content — the chips must stay React-rendered for `useSortable`, so the classic contentEditable technique is technically infeasible; the token spans stay React elements and the focused surface is simply not reconciled instead.
- **Adopting a rich-text editing framework (Slate, Lexical, contenteditable fallbacks)** — rejected: far beyond v0's plain-text needs (own text, line breaks, no formatting), and it would replace Task 1's sortable investment rather than extend it; the token document plus a pure parser reaches the same contract with the dnd-kit wiring intact.
- **A flat ordered token array in SnippetsContext with the focused surface owning its DOM** — chosen.

## Consequences

- Every character of the merged output belongs to exactly one token: `serialize(document)` is pure concatenation and the WYSIWYG invariant `flow.textContent === serialize(document)` holds at all times — including mid-typing and mid-drag.
- An unedited session keeps byte-identical copy output through source reconciliation and reorders alike: the move takes one adjacent `" "` separator token with the chip and replants it on whichever side of the landing point lacks one — separator hygiene is part of the move, never a renumbering pass (ADR 0001 amendment).
- Only snippet tokens are sortable; own-text and line-break tokens are never draggable, and the sorting announcements count snippet tokens.
- The mode-aware freeze contract makes the native undo stack best-effort: blurring, toggling edit off, or a non-text re-render replaces the surface's children from the model (a clean remount), which resets that surface's native undo stack — no custom undo in v0.
- Tombstones are in-memory session state only; persistence arrives with V1 (Merges CRUD).
- A browser without contentEditable degrades to the edit-OFF flow; the toggle stays the sole gate into editing, while dragging is always live in both modes.
